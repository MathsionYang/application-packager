# Inno 打包后端实施报告

日期：2026-10-14。实现文件：`packager/builder.py`、`packager/inno.py`；测试：`tests/test_builder.py`、`tests/test_inno.py`。未修改核心模型、存储模块或 UI，未增加依赖、初始化 Git 或运行任何安装程序。

## 已实现

- `build_bundle` 完全遵守 `INTERFACES.md`，可直接供 Qt 工作线程调用；构建开始时冻结配置，真实日志和进度通过回调传递。默认产品文件在 `%LOCALAPPDATA%/DesktopPackager/products.json`，显式 `profile_path` 同样支持。
- 直接以所选 A/B/C 发布目录作为 Inno 编译输入，索引所有发布文件、隐藏文件和空目录，保持相对目录结构。软件不再复制快照或逐文件通读计算输入哈希。编译前后比较文件集合、大小、时间戳、文件标识及类型；读取 PE 元数据期间入口改变也会停止构建。拒绝链接及重解析点，不修改原发布目录。
- PE 产品信息优先采用 ProductName/FileDescription 及 ProductVersion/FileVersion；缺失时使用入口文件名和 `1.0.0`。软件版本与总包版本独立。只读 PE 头识别 x86/AMD64/ARM64/ARM64EC，不加载执行输入文件；已知 AMD64 使用 `x64compatible`，ARM64 使用 `arm64`，其他/AnyCPU 保守保留默认模式。
- 持久化独立产品 AppId，身份键由角色、入口 EXE 文件名及产品名组成，不含绝对源路径、版本、输出路径或总包组合。产品文件原子写入，有线程锁及 Windows 文件锁；损坏时停止并保留原文件，避免悄悄生成新的升级身份。导出本次稳定产品配置。
- 每个子安装器有独立 AppId、带角色和 UUID 前缀的安装目录、角色标识的开始菜单组/桌面快捷方式/卸载显示名，避免不同角色同名产品覆盖快捷方式。复用原安装目录，不删除整个产品目录；常见 INI/CFG/CONFIG/数据库文件及常见配置目录使用 `onlyifdoesntexist uninsneveruninstall` 保留用户数据。
- 总安装器使用简体中文、现代向导；C 固定勾选，A/B 默认不勾选，只显示本包实际收录的软件。总包 `CreateAppDir=no`、`Uninstallable=no`。组件和任务名称同时标明角色与产品；已安装产品通过独立注册表键提示，摘要显示版本、目标目录及原始运行环境名称。
- 运行环境按列表顺序先执行，然后串行执行选中的软件。内嵌文件名唯一，原始同名环境包不会覆盖彼此，也不会修改位于既有输出目录的原始环境包。MSI 通过 `msiexec` 调用并强制追加 `/norestart REBOOT=ReallySuppress`；自建子安装器使用 `/VERYSILENT /SUPPRESSMSGBOXES /SP- /NORESTART /RESTARTEXITCODE=3010`。
- 检查进程是否启动、退出码是否被允许。MSI 1602/1641 始终停止；自建子安装器只接受 0/3010。3010 汇总后在完成页提示手动重启，总包通过自定义成功退出码返回 3010，不调用自动重启。失败或取消停止后续任务，展示已完成结果和日志位置，不伪报整体成功。安装时点击取消会等待当前安装进程退出，然后停止后续任务，不强杀正在修改系统的第三方安装器。
- ISCC 使用独立 argv 和 `shell=False` 启动，隐藏控制台；独立读取线程排空合并日志，主线程轮询取消。构建取消会终止正在运行的编译器。编译成功还必须验证本次特定目标存在且具有 PE 文件头，绝不依赖旧输出。
- 构建只在输出目录创建本次随机任务目录。完成编译和哈希校验后先原子发布构建记录，再原子发布最终 EXE。失败/取消保留状态清单及现有日志/脚本；清理范围只包含当前私有任务目录，旧安装包和输入文件保持不变。
- 产物包含 `manifest.json`、`config.json`、`products.json`、`README.txt`、脚本与完整编译日志。schema v2 清单标明 `direct_source` 和 `metadata_before_after`，软件输入仅记录相对路径、大小、修改时间及升级保留策略；环境包、子安装器、最终安装包和保留的证据文件仍记录 SHA-256。
- 用户数据分别按 Inno 指令值、节参数、Pascal 字面量、Source 编译路径处理转义。将 ISPP 内联分隔符切换到不在整个脚本数据中出现的随机标识，防止用户文件名/产品名中的 `{#...}` 被当成预处理表达式；支持中文、空格、单/双引号及字面花括号。

## 初版后端验证

使用官方示例 `D:\PCAPP\Inno Setup 7\Examples\MyProg.exe` 作为编译夹具；AMD64/ARM64 指令测试仅在临时副本修改 COFF machine 字段，验证生成和编译规则，不启动该副本。

命令：

```powershell
python -m pytest tests/test_builder.py tests/test_inno.py -q
```

结果：**22 passed**。测试覆盖四种实际组件组合的 Inno 编译、EXE/MSI 环境脚本、完整三软件总包真实构建、中文/花括号/预处理式路径、PE Unicode 元数据往返、AMD64/ARM64 实际脚本编译、同名角色快捷方式互不冲突、稳定产品标识迁移、产品文件损坏、源目录变化、取消正在运行的真实编译器、取消/失败清单、超过 1.6 MB 的子进程日志排空、退出码为零却无新输出，以及源环境包位于既有输出目录时保持不变。

所有测试只编译，不启动任何生成的安装程序、业务软件或运行环境包。安装顺序、升级保留、失败/取消、独立卸载及业务运行仍需在独立测试机实际验收。

## 本轮直接源目录验证

新增直接路径、软件不复制/全文哈希、manifest 元数据证据、编译时文件增删改、入口变化、链接拒绝及轻量预检回归。在原实现先确认 8 failed、3 passed 后修改。首次完整回归发现 Windows `DirEntry.stat` 的文件标识为零，与 `Path.lstat` 不一致；扫描统一使用一次 lstat 修复。源码冻结后，主任务完整测试 **57 passed in 17.38s**，保留实际 Inno 编译与 GUI 构建集成验证。独立审查没有发现高/中优先级问题。

## 已知边界

- 子安装器脚本引用原始软件目录；总包脚本仍引用任务清理后的子包和环境暂存路径。重建应通过应用导入配置，提供原始发布文件、环境包与稳定产品配置。软件输入不再具有内容哈希证据，不能仅凭元数据声称精确复现包内字节。
- 编译期间源目录应保持稳定。编译前后元数据检查可发现通常的增删改，无法保证识别保留所有元数据的内容替换；性能改动没有跳过 Inno 的文件读取和压缩。本轮未对用户实际软件 C 目录计时，不承诺固定加速倍数。
- 同一角色下完全相同的通用 EXE 名和产品名无法自动区分不同厂商产品；应使用独立产品配置文件。产品改名/入口改名时应迁移原有配置，避免生成新 AppId。已有外部安装版本需要人工将真实 AppId 写入产品配置并在测试机确认升级规则。
- 仅通过入口 PE 头识别已知原生架构，不推断所有依赖 DLL、OS 版本和运行环境条件。真实产品兼容性仍取决于完整发布目录。
- 用户数据保留采用保守通用规则。特殊授权文件、未知配置名称、数据迁移和专有升级逻辑无法仅凭发布目录推断，正式发布应逐产品验收。
- 第三方 EXE 安装参数没有通用标准；未知包以自身界面运行。其厂商提供的禁止重启参数须由操作者确认。总包及本工具生成的子安装器始终不自动重启；工具无法阻止一个自行重启系统的外部 EXE。
- 实际安装界面与安装退出码逻辑未在开发主机执行；本报告不把编译通过当作安装验收通过。
