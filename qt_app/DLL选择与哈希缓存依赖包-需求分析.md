# DLL 选择、哈希记录与依赖包复用

更新：2026-10-14。用户已同意按本文实施。

## 1. 目标与范围

选择 A/B/C 的发布目录后列出全部文件，由用户勾选其中的 DLL。所选 DLL 单独生成可缓存的依赖子包，其他文件继续进入原软件主包。C 必填、A/B 可选，三个软件独立安装、运行和卸载；总安装包先安装用户选择的 VC 等运行环境，再安装所选软件。

保留直接引用发布目录的构建方式，不复制整棵软件目录。不恢复说明卡或安装预览。文件列表不自动把整个第三方目录归组，不删除未勾选文件。

## 2. 操作流程

1. 在软件路径行点击“依赖文件”，后台枚举目录全部文件。只读取元数据，扫描时不计算内容哈希。
2. 表格显示相对路径、大小及状态，只有 `.dll` 可以勾选，扩展名不区分大小写。支持搜索、仅 DLL、仅已选和批量勾选。
3. 可导入上次记录，按角色与完整相对路径恢复选择；新增 DLL 默认未勾选。旧选择缺失时显示缺失，用户修正目录或明确取消选择后才能构建。
4. “保存记录”在后台计算当前所选 DLL 的 SHA-256 并保存 JSON。尚未生成依赖包的记录标为 `selection`，不声称可复用。已有匹配成功包时可连同 EXE 导出。
5. 正式打包时重新读取全部所选 DLL，按文件并行计算标准 SHA-256。导入只恢复选择，正式打包时完成一次必需比较，避免导入后自动哈希又在打包时重复读取。
6. 内容与规则一致且旧包校验成功，直接复用依赖子包；否则生成新的依赖子包。主软件子包和总包继续正常生成。
7. 成功包和对应记录一起发布；取消或失败不覆盖旧的成功基线。

总包中的 VC 等运行环境属于可选前置任务。它们自身启动失败、失败退出或用户在环境安装器窗口内取消时，记录警告并继续剩余环境包及软件；A/B/C 子安装器失败仍按软件安装失败处理并停止后续软件。总包向导的整体取消仍会停止整个任务。

安装包图标由用户在输出设置中选择 `.ico` 文件，生成总安装器时写入 Inno `SetupIconFile`；未选择时使用默认图标。图标必须位于软件源和输出目录之外。

人工保存记录与正式构建是两个独立任务：每次正式构建都重新校验所选 DLL，不把上次大小或修改时间相同当成 SHA 一致。

## 3. 文件列表与 Qt 交互

A/B/C 各有自己的选择集和记录路径，共用一种依赖文件窗口。主窗口仅显示已选 DLL 数量；进度和日志显示待校验、复用或重建等实际状态。

采用 `QTableView + QAbstractTableModel`，以相对路径表示目录结构，避免为几万个文件创建控件。复选框通过 `CheckStateRole` 提供。后台每批返回 500 条数据，GUI 线程更新模型。搜索节流，筛选不影响隐藏行的选择。29,000 条模拟数据自动排序实测约 4 秒，因此首版保留扫描顺序，不做自动排序。

导入后扫描尚未完成时，未发现的条目标为待定位；完整扫描后才标为缺失。扫描未完成时禁用“全选筛选结果”。关闭窗口或切换目录会取消旧任务，旧结果不得覆盖新目录状态。

同名不同目录的 DLL 独立处理，例如 `bin/a.dll` 与 `plugins/a.dll` 不合并、不平铺。选中路径必须为根目录内的普通 DLL 文件；拒绝目录穿越、链接/重解析点和 Windows 路径冲突。

## 4. 记录文件与缓存

记录使用 UTF-8 JSON，结构为：

```text
schema_version: 1
kind: selection 或 dependency_package
role: A / B / C
source_hint: 上次发布目录（仅供定位）
files: [{path: 完整相对路径, size: 字节数, mtime_ns: 辅助信息, sha256: 标准文件摘要}]
recipe: 安装布局、产品身份、架构、压缩设置、生成器及编译器指纹
cache_key: 排序文件集合与 recipe 的规范化 SHA-256
package: {path: 依赖 EXE 路径, size: 字节数, sha256: 包摘要} 或 null
```

`source_hint`、文件修改时间不进入内容缓存键，目录整体迁移后仍可按相对路径恢复。产品 AppId、架构和安装规则参与判断。跨电脑迁移产品时仍需同时迁移原有 `products.json`，保持产品身份。

选择记录和成功包记录严格区分。本次 DLL 摘要单独保存，不能先把新摘要写进旧成功包记录，再据此误判旧 EXE 可复用。

缓存放在应用数据目录的 `cache/dependencies/`，在 `.build-*` 之外。每次生成写入新的一代目录，校验 EXE 后原子发布；总安装包及构建记录成功发布后，才激活该键的新指针。后期取消可能留下未激活的完整代，不替换旧基线。旧代不原地覆盖，损坏缓存可生成新代修复。工具链指纹覆盖 ISCC、编译器/压缩 DLL、安装器模板及相关语言和图资源。

可移植导出由 JSON 和同名 `.files` 文件夹组成，文件夹内包含依赖 EXE；JSON 使用相对包路径。只复制 JSON 不等于复制依赖包。导入包缺失时，可从完整的当前 DLL 重建。

## 5. 复用判断

| 本次情况 | 处理 |
| --- | --- |
| 选中路径、全部 SHA、recipe 一致，缓存 EXE 存在且 SHA 正确 | 复用依赖包 |
| 任意选中 DLL 内容改变 | 重建该软件的整个依赖子包 |
| 增加/取消勾选，或选中 DLL 改名/移动 | 重建该软件的整个依赖子包 |
| 新增未勾选 DLL | 新 DLL 留在主包，不单独使依赖缓存失效 |
| 所选 DLL 缺失或不可读 | 停止，要求修正目录或明确取消选择 |
| 缓存包缺失、损坏或规则变化 | 当前文件完整时重建 |
| 没有勾选任何 DLL | 沿用原主包，不生成依赖子包 |
| 哈希/编译期间源文件变化、取消或失败 | 不发布本次有效基线 |

一个 solid 依赖 EXE 中任意成员变化，一般都需重编整个依赖 EXE，首版不承诺仅替换变化文件的压缩块。A/B/C 分别缓存，某一软件变化不会要求另一软件的依赖包一起重建。

## 6. 安装和卸载责任

推荐将依赖子 EXE 作为透明的解压辅助器，而不是另一个可见产品：`Uninstallable=no`，无快捷方式、无产品注册项。依赖 EXE 按原相对路径打包所选 DLL。

原软件子安装器以 `dontcopy nocompression` 嵌入依赖 EXE，在 `PrepareToInstall` 阶段启动辅助器，将 DLL 解压到主安装器私有临时目录。随后原软件 `[Files]` 使用 `external` 条目从临时目录复制 DLL 到 `{app}` 下对应的原相对位置。

主安装器为外部 DLL 指定 `ExternalSize` 和 `Hash`。Inno 在安装复制时校验内容，不需要先完整哈希再复制。辅助器嵌入主包时也指定包的 `Hash`，依赖源条目指定本次 DLL 的 `Hash`，把记录与实际编译/安装内容绑定。

分组不改变既有升级策略：通常 DLL 使用 `ignoreversion`；被现有配置目录规则识别为保留文件的条目，继续保持 `onlyifdoesntexist uninsneveruninstall`。

最终文件仍由原软件 `[Files]` 及其原卸载日志管理；主软件 AppId、历史安装目录和卸载日志位置保持稳定。这样旧版全量安装升级为拆包安装、DLL 在两组间切换，都不会转交到另一个独立卸载器。失败的辅助解压只影响临时目录，尚未改动最终软件目录。

辅助器的成功退出不等于整个软件安装成功，外层仍以原软件子安装器结果为准。最终主软件安装保持 Inno 原有升级/回滚行为。旧版已安装且新版本删除的文件遵循既有产品升级策略，不擅自删除源目录中未出现的用户文件。

代价是安装时需要临时空间存放依赖 EXE 和解压后的 DLL，并增加从临时目录向最终目录的一次复制。软件安装后目录树与原发布目录保持一致；真实 DLL 与 `.pyd` 的兼容性仍需产品运行验证。

## 7. 多线程与加速边界

哈希使用一个有界线程池，默认 2 个工作线程，界面允许调整为 1–8。本机 SATA SSD 可比较 2/4/8 的实测吞吐；不是线程越多越快。按文件并行，每个 DLL 使用单个 SHA-256 对象顺序读取约 1 MiB 块，不能将分块摘要拼接当作标准文件摘要。队列限制在工作线程数的小倍数，避免一次提交几万个任务。

线程定期检查取消，进度以已读字节和文件数更新并节流，不直接操作 GUI。文件读取前后核对状态，读取中变化不得生成有效记录。哈希和压缩分阶段，防止同时争抢同一磁盘。

子包采用 `lzma2/normal`、solid 压缩和最多 4 个 LZMA 块线程（按 CPU 数限定）。先顺序编译各软件，避免多套压缩器争抢本机 8 核。外层对已经压缩的子包不再次压缩。

初次仍需所选 DLL 的哈希与压缩；缓存命中后省掉所选 DLL 的再次压缩，但仍需当前 DLL 哈希、缓存 EXE 校验及总 EXE 的读写。未选 `.pyd`、Python 模块、数据等仍在主包重新压缩。不承诺未经实测的加速倍数。

## 8. 验收

- 完整扫描与筛选后勾选集合稳定，同名 DLL 不混淆；缺失项可见，新增项不自动勾选。
- 同大小、同 mtime 的 DLL 内容改变仍触发重建。
- 未改变文件、移动根目录、恢复历史记录可正确复用；改选择/改规则/缓存损坏会重建。
- 记录导出包含可迁移包，选择记录不能伪装成功包；取消、失败保留旧代。
- 使用真实 Inno 编译验证 helper、external/Hash 主子包及总包；不会在开发机器运行用户安装器。
- Qt 后台扫描/哈希可取消，窗口关闭不遗留运行中的 QThread。
- 运行现有回归、新功能测试，并重新生成 EXE/ZIP，核对产物和发布记录。
